# 需求 Spec：巴黎城市时空文化地图

---

## 1. 背景与目标

### 需求来源

参考境内项目 **StoryMap**（cuizicheng1024/storymap）的底层框架与设计思路，做一个聚焦境外城市的时空文化地图。参考项目以**历史人物**为主体、面向**中学教学**；本项目以**城市 POI** 为主体、面向**旅游娱乐**，MVP 聚焦巴黎。

### 业务目标

1. 把巴黎的文化记忆变成**可读、可逛、可讲给朋友听**的故事——看到一个地点，就知道这儿发生过什么、谁待过、哪本书写过它、哪部电影在这取过景。
2. 建立一套**自动化交叉验证**的内容生产管道，使内容既可靠又不依赖人工逐条核实。
3. 验证「城市 × 文化 × 时空」这一产品形态，为后续扩展到其它境外城市打底。

### 成功指标

- **核心定性指标**：用户愿意截图分享某个 POI 的故事；用户能被一条故事线勾住、一路点到底。
- **内容质量指标**：Hero 层 POI 的事实字段 100% ≥L2 置信度；自动质检通过率 ≥70%。
- 量化运营指标（DAU / 留存 / 分享率）待产品上线前补充。

### 市场机会（调研结论）

- **Paris ZigZag**：巴黎本地头部文化品牌，58 万粉丝、月访问 50 万，**却没有地图、没有 App，且刚退出体验业务**。
- **Secret City Trails**：覆盖 50+ 欧洲城市，**唯独没有巴黎**。
- 数据侧异常慷慨：14,760 条带片名的官方取景地、2,619 块名人铭牌、Atget/Marville 老巴黎影像全套 CC0 可商用。
- **结论：内容原料免费且顶级，缺的是把它组织成「可走的故事」的产品。**

## 2. 用户与场景

### 目标用户

- **主力**：计划去巴黎旅行、或刚从巴黎回来的中文用户。对文艺内容有兴趣，但不愿读长文。
- **次要**：影视与文学爱好者（《午夜巴黎》《天使爱美丽》《爱在日落黄昏时》受众）、法语学习者、云旅游人群。

> 用户不是研究者也不是学生。**「有梗、能拍照、能讲给朋友听」比「历史意义重大」更重要。**

### 核心场景

1. **行前找灵感** — 在桌面端做攻略，浏览地图与故事线，发现有意思的地方，规划想去哪些地方。
2. **云逛巴黎** — 不一定真要去，就是喜欢看这座城市的故事；被某个 POI 或某条线勾住，一路点下去。
3. **行后回味与分享** — 把某个 POI 的故事、某条走过的路线分享出去，作为谈资。

> **本产品定位为「行前 + 行后」的桌面端体验，不覆盖「人在巴黎街头掏手机现场打卡」的场景**（见第 5 节非目标）。因此详情页的对应模块为「**📷 这地方为什么好看**」——讲视觉特征与画面感，服务于想象力和分享欲，**不是现场拍摄指引**。

### 产品调性

**旅游向 + 一点点文艺 + 主要是娱乐轻松向。** 文案风格是「一个懂行的朋友带你逛」，不是导游词也不是维基百科，可以有幽默和吐槽。

## 3. 功能需求

### 3.1 POI 内容体系

- **功能描述**：以巴黎 POI 为主体，每个 POI 承载「这里发生过什么、关联哪些名人/作品/影视」的层层故事。
- **分层**：
  | 层级 | 数量 | 内容深度 | 生产方式 |
  |------|------|---------|---------|
  | Hero（核心） | 约 40 | 深度内容 + 人工终审 | 半自动 |
  | Story（次级） | 约 100 | 轻量内容 | **全自动** |
  | Pin（长尾） | 约 160 | 仅列点 | **全自动** |
  | **合计** | **约 300** | | |
- **选点原则**：优先选**能同时挂 3–5 条故事线**的 POI，让内容密度显著高于条目数。典型如旺多姆广场（肖邦逝世 + 《Lupin》黑珍珠劫案 + 库尔贝推倒纪功柱，一点三线）。
- **覆盖范围**：核心街区优先——拉丁区、圣日耳曼、蒙马特、玛黑。

### 3.2 故事线体系（主题为主体，人格为标签）

- **功能描述**：把 POI 用**主题**串成可消费的线路。POI 与故事线是**多对多**关系。
- **组织逻辑**：**核心是「主题故事线」** —— 每条线有自己独立的主题魅力（海明威的巴黎、蒙马特的画家们、铜牌都写错了……）。**人格是给每条主题线打的标签**，用于测试后的匹配推荐，而不是线路的生成逻辑。
- **规模：16 条主题线，每条对应一种旅行人格**（一一对应，覆盖全部 16 种）。

> ⚠️ 不是「为 16 种人格各造一条线」。若按人格造线，会导致同一批 POI 换个说法讲 16 遍、内容严重同质。正确做法是**先有好主题，再判断它天然吸引哪类人**。

#### 3.2.1 人格模型（沿用既有「旅行人格测试」，不改设定）

4 个维度各自二分，组合出 16 种人格：`culture`（文化）· `planning`（规划）· `social`（社交）· `spending`（消费）。

| 维度组合 | 高社交+高消费 | 高社交+低消费 | 低社交+高消费 | 低社交+低消费 |
|---|---|---|---|---|
| **高文化+高规划** | 全能管家 GOAT | 宝藏团长 CTRL | 深藏Blue之人 BLUE | 学者 NERD |
| **高文化+低规划** | 干就完了 DODO | 拾光者 MYTH | 大小姐 LORD | 清冷佛子 BUDD |
| **低文化+高规划** | 煤老板 BOSS | 时间管理大师 TIME | 多比 FREE | 追风筝的人 WIND |
| **低文化+低规划** | 慈善家 SHAN | 小蜜蜂 BEE | 休息者 REST | 史莱姆 CUTE |

> 人格名称、代号、特点、标签、描述文案**以原文档为准，不得改写**。

#### 3.2.2 主题线 ↔ 人格的匹配依据

每条主题线按其内在气质，判定四个维度的高低，从而落到唯一人格：

| 维度 | 判定这条线属于「高」的特征 | 判定属于「低」的特征 |
|------|------------------|------------------|
| **culture** | 主题依赖历史纵深、典故、人物关系、文本互文 | 主题以体验、视觉、氛围、好玩为主 |
| **planning** | 有明确站序、时长、最佳时段，路线紧凑 | 点位松散，走到哪算哪，无强制顺序 |
| **social** | 途经咖啡馆、市集、酒吧、现场演出等适合结伴搭话的场所 | 以书店、公墓、小美术馆、清晨时段等独处场景为主 |
| **spending** | 需进店消费、有体验项目、推荐坐下点单 | 以街景、公墓、外观、公共空间、免费时段为主 |

**站点清单**：第 10–16 条线共 **57 站**，完整站序、逐段距离、状态标记与跨线复用关系见 `docs/station-list.md`；字段级事实与信源见 `research/storyline-*.md`。

> **主题名的信源约束**：主题名是整条线的信誉承诺，出现在首页、分享卡片与搜索结果中，**不可挂徽章、不可静默降级**。因此**主题名只能建立在 L1–L2 素材上**。第 10 条线原拟名《达利要了一群羊》因该掌故为酒店单一来源（L4）而弃用——L4 可以进内容，不能进门面。


#### 3.2.4 POI 复用规则

- **核心 POI 允许大量重合**，这是设计预期而非缺陷。16 条线共用一个 POI 池。
- 每条线 **5–8 站**，其中允许 **1–3 站为该线专属**。
- 重合的 POI **在不同主题线下叙事角度不同**。例：花神咖啡馆在 NERD 线讲 1939 年的煤炉与存在主义谱系，在 REST 线讲"找个位子坐一下午没人赶你"。但这是**主题差异带来的自然结果**，不是为了凑人格而刻意改写。

#### 3.2.5 单站字段与业务规则

- **单站字段**：地址 + 坐标、**是否仍存在可访问**、80–150 字叙事、关联名人/作品/影视场景、📷 这地方为什么好看、2+ 信源、置信度徽章。
- **业务规则**：
  - 步行距离与时长**必须诚实标注**。《爱在日落黄昏时》实测 10.1km / 3–3.5 小时，而电影只有 80 分钟——不得宣传成「实时走完电影」。
  - 高 planning 人格对应的线须给明确站序与时长；低 planning 对应的线不强制顺序。
  - 支持**日/夜双段结构**（如《午夜巴黎》线以钟敲十二下为分界）。
  - 允许同一街区承载**态度相反**的两条线（海明威线「拆穿传说」vs 午夜巴黎线「享受传说」）。
  - **跨城市站点须显式标注**：含巴黎市域外站点（如吉维尼距巴黎约 75km、凡尔赛需 RER 45 分钟）时，标为「需单独一日」并排除在步行距离统计之外。

#### 3.2.6 人格测试入口

- 提供 **12 题人格测试**（题目与选项文案以原文档为准），4 个维度各 3 题，每题 0/1/2 分，维度总分 ≥4 判为「高」。
- 测试完成后进入结果页（人格名称 / 英文代号 / 特点 / 一句话标签 / 结果描述），并**推荐对应的那条主题线**。
- 支持「再次测试」与「分享结果」。
- **测试不是强制前置**：未测试的用户可自由浏览全部 16 条主题线；每条线也都展示自己的人格标签，用户可反向按人格找线。

### 3.3 知识库与内容生产管道（核心模块）

> **语料库必须自建，不能偷懒。** 这是本项目的护城河。

#### 3.3.1 数据源

> **MVP 不商业化，不考虑版权风险，以能用好用为准。** 下表的许可列仅作记录，不构成选型约束；若未来转向商业化，需重新评估 ODbL 传染性与 Gallica 图像授权。

| 用途 | 数据源 | 许可（仅记录） |
|------|-------|------|
| **底座** | POP / Base Mérimée（巴黎 1,893 条） | Licence Ouverte 2.0 |
| **实体与坐标** | Wikidata（巴黎带坐标 28,771） | CC0 |
| **人物-建筑关联** | 巴黎铭牌数据集（2,619 条含铭文全文）+ Open Plaques（1,058 条） | ODbL / PDDL |
| **影视取景** | `lieux-de-tournage-a-paris`（14,760 条）+ Wikidata P915（153 精确点） | ODbL / CC0 |
| **配图** | Paris Musées CC0（含 Atget/Marville 老巴黎街景）、Wikimedia Commons、Gallica | 不限 |
| **POI 属性** | OSM / Overpass | ODbL |
| **历史地籍** | ALPAGE（Vasserot 地籍图 910 幅已矢量化） | ODbL |

**⭐ 关键架构约束**：Wikidata 的 `P19/P20/P551`（出生/逝世/居住地）**绝大多数只解析到「区」级**，落不到建筑。因此**「某名人住过这栋楼」必须靠铭牌数据集 + Open Plaques**，不能靠 Wikidata。

**技术性排除**（非版权原因）：IMDb / TMDB —— **均无取景地字段**，取景数据只能靠巴黎市政许可数据集 + Wikidata P915。Google Places —— 禁止预取落库，与建知识库的工作方式冲突。

**工程约束**：Overpass 公共实例不可作为线上后端，须一次性抽取自建。

#### 3.3.2 置信度分级（字段级，非 POI 级）

**独立源判定**（硬编码，避免同一事实被数三遍）：Wikidata ↔ 同语种 Wikipedia **不算独立**；OSM 带 `wikidata=*` 标签时与 Wikidata **不算独立**；市政/文化部一手数据与任意源**算独立**。

| 等级 | 阈值 | 呈现 |
|------|------|------|
| **L1 高置信** | ≥3 独立源一致 | 无标记，可用肯定句 |
| **L2 中置信** | 2 独立源一致 | 必须用限定语「一般认为」 |
| **L3 单源** | 1 个官方/一手源 | 标注「据（来源）记载」 |
| **L4 传说** | 单二手源或多源矛盾 | 强制「坊间传说」徽章 |
| **L5 已证伪** | 存在权威否证 | 不作事实展示，转「辟谣卡片」 |

**Hero 层准入**：主叙事所有事实 ≥L2 且至少一条 L1。

#### 3.3.3 内容判真法则（入库判据）

> **能说清「为什么是这家、哪一年、什么具体细节」的掌故大概率是真的；只有一串名字的，那是菜单的一部分。**

**工程化**：每条人物-POI 关联必须填 `why_here` + `when` + `detail` 三字段，**缺一即自动降为 L4**。

#### 3.3.4 冲突处理规则（命中即停）

| # | 规则 |
|---|------|
| C1 | 源权威分层：一手行政/普查 > Wikidata（带引用）> Wikipedia > 媒体 > 旅游博客 |
| C2 | 时间新鲜度：「当前状态」类字段由**最新有效源直接覆盖**，不做多数表决 |
| C3 | 数值容差：年份差 ≤1 取早值；坐标差 >50m 进人工仲裁 |
| C4 | **同名歧义强制阻断**：名称相似度 >0.85 但距离 >500m 时告警 |
| C5 | 官方沉默即负面信号：权威源系统性标注中的缺失项，置信上限锁 L2 |
| C6 | **实物 vs 记载矛盾**：铭牌与文献矛盾时两者都存，标「实物记载有误」，不裁决 |
| C7 | **台词 vs 实拍分离**：建两条独立记录，各标 `is_diegetic` |
| C8 | 全不命中 → 降 L4 + 人工队列（预计 <2%） |

#### 3.3.5 LLM 红线（工程强制，不靠 prompt 约束）

**绝对禁止 LLM 生成**：坐标、门牌号、行政区、年份、日期、人物-地点关联、取景地事实、营业时间票价、**引文/台词/铭文原文**（幻觉最高发区）。

**允许 LLM 生成**：一句话钩子、氛围描述、叙事过渡句——但仅可重组已验证事实。

**强制手段**：LLM 输入是 **fact sheet（已验证事实的结构化 JSON）**而非自由文本；输出后跑**回指校验**——抽出文案中所有数字/专名/地址逐一比对 fact sheet，出现表外实体即整条重生成，连续两次失败降级模板文案。

#### 3.3.6 端到端流水线

```
[0] 候选池构建 → [1] 地址归一化 → [2] 实体对齐（C4 在此执行）
→ [3] 交叉验证打分（坐标须 ≥L2 否则淘汰）→ [4] 分层打分
→ [5] 标签挂接 → [6] Fact Sheet → [7] LLM 文案 → [8] 自动质检
→ [9] 入库发布（Hero 需终审）→ [10] 每月持续校验
```

**人工介入仅 4 处**：① 街区多边形一次性绘制；② 坐标冲突 >50m 仲裁（<1%）；③ 质检两连败的 Hero 条目；④ Hero 终审与精品线策展。
**Story + Pin 层约 260 个 POI 全自动，无人工核实环节。**

### 3.4 差异化内容层：「铭牌怎么说 vs 实际发生了什么」

- **功能描述**：把交叉验证的副产物做成独立内容层。**目前没有任何竞品地图有这个角度。**
- **素材已就绪**（调研共推翻 40 条流传说法），其中最有价值的是**巴黎官方铭牌本身就有错**：
  | 铭牌说法 | 实际 |
  |---------|------|
  | 皮雅芙生于贝尔维尔街 72 号台阶上 | 出生证明写的是 Tenon 医院 |
  | 普罗可布咖啡馆铭牌写 1656 年 | 实为 1686 年，给自己早写了三十年 |
  | 雨果故居说 1832 入住 | 同一面墙的铭牌说 1833 |
- 其它高价值辟谣：《天使爱美丽》照相亭在**北站**不是东站（"NORD"被改成"EST"）；《红磨坊》(2001) **在巴黎零取景**（全片悉尼拍摄）；《John Wick 4》凯旋门戏**在柏林废弃机场拍**；圣叙尔皮斯日晷**不是**巴黎子午线。

### 3.5 徽章与标注体系

| 徽章 | 等级 | 文案 |
|------|------|------|
| 🏛 有据可查 | L1 | （不显示） |
| 📎 大家都这么说 | L2 | 「多数资料指向这里，但没有一锤定音的证据。」 |
| 🗝 只有一个出处 | L3 | 「这件事只在（来源）里出现过一次。」 |
| ✨ 未经证实，但很好听 | L4 | 「查无实据，不过我们决定留着。」 |
| 🔍 著名的假故事 | L5 | 「这个传说太有名了，有名到值得专门讲讲它是怎么假的。」 |

**三条正交的实用标注**（直接影响差评率）：🚪 只能在外面看 ｜ 🤫 私宅请轻声 ｜ ⏳ 需预约/看季节

**特殊类型标注**：「**主体，非取景地**」——用于红磨坊这类名气来源于此但未在此拍摄的 POI。

### 3.6 搜索与筛选

- **多维搜索**：支持中文名、法文原名、英文名、别名。**把匹配原因暴露给用户**（沿用参考项目做法）。
- **别名重定向**：巴黎 POI 的中/法/英多名互相跳转。
- **片名别名表**（必需）：大制作用代号报备（《碟中谍6》报备名为 `GEMINI`），需建立映射。
- **筛选维度**：主题（文学/艺术/影视/音乐/历史）、时代（7 段）、街区。

### 3.7 时间维度

**⭐ 整个赛道没有一个产品把年代当成一等筛选维度**，这是核心差异化点。

**7 段时间分层**（与铭牌数据集 `periode_1` 字段天然对齐）：

| # | 时代 | 年份 |
|---|------|------|
| 1 | 旧制度 / 启蒙 | –1789 |
| 2 | 大革命与帝国 | 1789–1815 |
| 3 | 十九世纪浪漫主义与奥斯曼改造 | 1815–1870 |
| 4 | 公社与美好年代 | 1871–1914 |
| 5 | **迷惘的一代** | 1918–1939 |
| 6 | **战后与存在主义** | 1940–1959 |
| 7 | 新浪潮到当代 | 1960– |

> 每段都同时有「人物 + 作品 + 影视 + 事件」四类内容。第 5、6 段内容最厚、国际认知度最高，作为首发主推。

**两层时间字段**：`事件年代`（雨果住此 1832–1848）+ `素材年代`（这张 Marville 照片摄于 1865），分别驱动「按年代筛地图」与「今昔对照」。

### 3.8 双语与全局语言切换

- **功能描述**：全站支持**中英双语**，提供**全局语言切换**入口，切换后所有界面文案与内容文案同步切换，语言偏好在会话内保持。
- **业务规则**：
  - 语言切换为**全局**行为，不是逐页设置。切换时保持当前页面与状态（含故事线的 `#loc=N`）不丢失。
  - **专名三语并存**：POI 名称同时存储中文名、**法文原名**、英文名。法文原名在两种语言下**始终显示**（这是实地找路的依据，不可只显示译名）。
  - **译名走固定词表**：人名、作品名、影视片名的中文译名由词表管理，词表外的进人工，不允许 LLM 自由翻译。
  - 中英文案**不是互译关系而是各自撰写**——中文面向中文用户介绍巴黎，英文面向国际游客，梗与语气可以不同。但**事实字段（坐标/年份/关联/取景地）必须完全一致**，共用同一份 fact sheet。
  - 置信度徽章、实用标注（🚪🤫⏳）需提供双语文案。
  - 引文、台词、铭文原文**保持原始语言**（法文铭文不翻译成英文再翻回来），可附译文但须标明。
- **对内容生产管道的影响**：
  - fact sheet 保持语言无关（纯结构化事实），LLM 文案生成阶段按语言分别产出两份。
  - 回指校验对两种语言各跑一次。
  - **叙事文案量约翻倍**（事实层不翻倍，两语言共用同一份 fact sheet）。
- **降级策略**：若某条目英文文案缺失，回退显示中文并标注，不阻塞发布。

## 4. 页面与交互

> 严格参考 StoryMap 的交互链路。**最小化修改原则**：保持架构与数据流不变。

### 4.1 主用户旅程

```
【入口 A · 测试驱动】
打开首页 → 「测测你是哪种旅行人格」→ 12 道单选题
  → 结果页（人格名称 / 代号 / 特点 / 标签 / 描述）
  → 推荐「最适合你的那条巴黎线路」→ 进入该主题线
  → 分享结果

【入口 B · 自由探索】
打开首页（巴黎全城地图）
  → 拖动时间轴 / 点主题筛选 → POI 随之亮起或变暗
  → 点击某个 POI marker → 卡片浮层（名称 / 一句话钩子 / 置信徽章）
  → 进入 POI 详情页 → 看这个地点的层层故事
  → 从 POI 页跳进它所属的某条主题线

【共同的深度消费路径】
主题线页：左侧站点时间轴 ⟷ 右侧地图轨迹（双向联动）
  → 点「自动播放」逐站推进，或手动点某站
  → 分享某一站（#loc=N 深链）或整条线
  → 从某站的关联 POI 跳到另一个 POI → 无边界游走
  → 也可从线路页的人格标签，横向跳到其它 15 条线
```

**页面间关系**：首页（地图 + 测试入口）→ 测试页 → 结果页 → 主题线页 ⟷ POI 详情页，POI 与主题线多对多互跳。

### 4.2 首页：巴黎全城地图 + 时间轴

- **页面用途**：一眼看到整座城市的文化密度，并能按时代/主题切片。
- **核心元素**：
  - 巴黎全城地图（MapLibre），POI 以 marker 呈现，**不做聚合**（沿用参考项目做法，保留颜色与 hover 卡片可见性）
  - **底图必须是真实可交互的街道级地图**（详见 4.2.1），不接受示意图、色块占位或静态图片
  - **时间轴**：7 段时代预设 + 可拖动起止年 + 框选刷取 + 双击重置。拖动时**实时刷新窗口内 POI 数量**
  - 主题筛选器（文学/艺术/影视/音乐/历史）
  - 搜索框（含建议下拉，展示匹配原因）
- **交互**：
  - 时间轴拖动 → **地图 marker 显隐/大小/高亮同步刷新 + 计数实时更新**
  - hover marker → tooltip 卡片（名称 / 年代 / 一句话钩子）
  - 单击 marker → 浮层卡片 + 「查看详情」按钮
  - 双击 marker → 直接进 POI 详情页
- **状态**：加载中、筛选后空态（「这个时间窗里巴黎很安静」）、地图加载失败降级

#### 4.2.1 底图方案（高保真，不商业化）

**验收口径：底图必须能看清街道名、建筑轮廓与塞纳河走向，能缩放到单栋建筑级别。** 任何用色块、SVG 示意图、静态截图或纯 marker 画布冒充地图的做法均不合格。

**不考虑版权与商业授权**，按「能用好用」选型，优先级从高到低：

| 优先级 | 方案 | 说明 |
|---|---|---|
| **首选** | **MapLibre GL JS + 免 key 的公开矢量瓦片** | 矢量瓦片支持无级缩放、旋转、自定义配色，最贴合「老地图 / 旧书封面」视觉。可直接用公开的 OSM 矢量瓦片服务或自托管 Protomaps pmtiles（巴黎单城约 100MB，静态托管即可） |
| **次选** | **MapLibre / Leaflet + OSM 栅格瓦片** | `tile.openstreetmap.org`、Stadia Maps Stamen（Toner / Watercolor 复古风，与项目调性极搭）、CARTO Positron / Dark Matter。接入简单、零配置 |
| **兜底** | 任何能立刻跑通的公开瓦片源 | **绝不因为选型犹豫而退回示意图** |

**视觉要求**：底图配色需与全站的「老地图 / 旧书封面 / 法式海报」视觉语言统一——建议低饱和米黄或墨黑单色调，让彩色 POI marker 成为画面主体。Stamen Toner / Watercolor 可直接满足，自定义 style JSON 亦可。

**必须具备的地图能力**：缩放（滚轮 + 按钮）、拖拽平移、`flyTo` 平滑飞行（主题线联动依赖）、marker 图层、GeoJSON 折线（主题线轨迹）、attribution 显示。

### 4.3 POI 详情页

- **页面用途**：讲透一个地点的所有故事。
- **核心元素**：
  - POI 头部：名称（中/法）、所在区、地址、**是否仍存在可访问**、置信徽章、实用标注（🚪🤫⏳）
  - 一句话钩子 + 主叙事
  - **关联实体区**：关联名人 / 文学作品 / 影视场景（每条带 `why_here` + `when` + `detail`）
  - **📷 这地方为什么好看**（**替换参考项目的「教材知识点 / 考点」模块**）：讲这个地点的视觉特征、画面感、有什么梗——服务于「想象力与分享欲」，不是现场拍摄指引
  - **所属故事线**：该 POI 出现在哪几条线里，可直接跳入
  - **辟谣卡片**（若有 L5 内容）
  - 小地图 + 周边 POI
- **状态**：内容缺失时不显示空区块；L4/L5 内容强制带徽章

### 4.4 主题线页

> 这是参考项目交互复用度最高的页面——结构等价于原「人物页」，只是主角从「一个人的一生」变成「一条主题线的若干站」。

- **页面用途**：带用户走完一条主题线。
- **核心元素**：
  - 线路头部：线名 + 一句话钩子 + **匹配的人格标签**（可点击，展示该人格描述）+ 主题标签 + 时代 + **诚实的步行距离/时长** + 适合人群与最佳时段
  - **左侧：站点时间轴**（序号 / 站名 / 年代 / 阶段徽章 / 该站叙事）
  - **右侧：地图轨迹**（按顺序连接各站，分段配色渐变，带方向箭头）
  - 地点浮卡（当前站的名称 + 故事）
  - 播放控制：「自动播放」「上一站 / 下一站」
  - 「查看完整轨迹」（fitBounds 到全部站点）
  - 全屏查看 + 生成图片
  - **底部：其它 15 条线的入口**（按人格网格排布，可横向探索）
- **交互（核心，完整继承参考项目）**：
  - **双向联动**：点时间轴卡片 → 地图 flyTo 该站；点地图 marker → 时间轴对应卡片高亮
  - **自动播放**：每约 2 秒推进一站，时间轴高亮 + 地图飞行 + 浮卡换内容 + URL hash 同步
  - **`#loc=N` 深链**：分享出去直接落到第 N 站，全状态就位，浏览器前进后退可用
- **状态**：加载中、地图降级提示；低 planning 的线不展示强制站序编号

### 4.5 人格测试页与结果页

- **页面用途**：用轻量测试帮用户找到「属于自己的那条巴黎」，同时作为分享裂变入口。
- **测试页**：
  - 12 道单选题，每题 3 个选项，题目与选项文案**以原文档为准不得改写**
  - **单题单屏**：一屏只呈现一道题，避免列表式滚动
  - **点击选项即自动进入下一题**，无需「下一题」按钮。点击后选项给出短暂的选中反馈（约 200–300ms）再切题，让用户确认自己点中了什么
  - 题间切换用横向滑入动效，进度条同步推进
  - **答完第 12 题自动进入结果页**，不需要「提交」按钮
  - 进度指示常驻（如「7 / 12」+ 进度条）
  - 支持返回上一题修改；返回时该题的原选项保持选中态，重新点击任一选项即覆盖并再次自动前进
- **结果页**：
  - 人格名称 + 英文代号 + 特点（四维度组合）+ 一句话标签 + 结果描述（**文案以原文档为准**）
  - **推荐对应的那条主题线**（主 CTA）
  - 「再次测试」入口
  - 「分享结果」按钮
  - 次要入口：查看全部 16 种人格与对应线路
- **业务规则**：4 个维度各 3 题，每题 0/1/2 分，维度总分 **≥4 判为「高」**，<4 判为「低」
- **状态**：中途退出不保留进度（重新开始）；结果可通过 URL 分享并直达

### 4.6 全局交互规则

- **三级信息密度**（沿用参考项目）：hover → tooltip 卡片；click → 选中 + 联动；dblclick → 跳转页面
- **无需登录**：MVP 不做账号体系
- **分享**：任意 POI 页、主题线页、主题线某一站、人格测试结果，均可生成可分享链接
- **首页需同时承载两个入口**：巴黎全城地图（自由探索）+ 人格测试（引导发现）

### 4.7 交付形态与语言

- **桌面优先**，完全对齐参考项目的布局与技术架构（纯静态站）。移动端保持基础可用（不崩版、地图可用），但不做移动端专项优化，也不承诺现场使用体验。
- **中英双语 + 全局语言切换**（详见 3.8）。语言切换入口放在全局头部，切换后保持当前页面与状态。
- POI 的**法文原名在两种语言下始终显示**。

## 6. 验收标准

- [ ] Hero 层约 40 个 POI，主叙事事实 100% ≥L2 置信度，且每个至少含一条 L1 事实
- [ ] 每条人物-POI 关联均填写 `why_here` + `when` + `detail`，缺项者已自动降级 L4
- [ ] 所有 L4 内容带「坊间传说」徽章，所有 L5 内容以辟谣卡片形式呈现而非事实展示
- [ ] **16 条主题线全部产出**，与 16 种人格一一对应，无遗漏无重复
- [ ] 16 条线全部标注**实测**步行距离与时长，无夸大表述
- [ ] **第 10–16 条线的补充素材均为真实检索所得，无硬凑**——每个新增 POI 都走完整交叉验证流程
- [ ] 每条线 5–8 站，且至少有 1 站为该线专属
- [ ] 所有 POI 标注「是否仍存在可访问」，状态类字段带 `last_verified_at`

- [ ] **底图为真实街道级地图**：可看清街道名与建筑轮廓、可缩放至单栋建筑、可拖拽平移、支持 `flyTo` 平滑飞行。示意图 / 色块 / 静态截图均不通过
