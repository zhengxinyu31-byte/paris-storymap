# Paris StoryMap

> 巴黎城市时空文化地图 — 把一座城市的 POI、名人、作品与影视场景，重新缝回它们发生的时间和地点上。

**Paris StoryMap** is a bilingual (中文 / English) spatio-temporal culture map of Paris. Unlike guidebooks that tell you *what to see*, it tells you *what happened here, when, and why anyone should care* — with every claim traced to at least two independent sources.

当前阶段：**需求定稿，原型迭代中**。尚未进入开发。

---

## 这是什么

大部分巴黎旅游产品告诉你「花神咖啡馆很有名，萨特去过」。

本项目告诉你的是：1939 年那个冬天巴黎缺煤，花神是少数烧得起煤炉的地方，所以萨特和波伏娃每天开门就来、关门才走——**他们不是在那里发明存在主义，他们是在那里取暖，顺便发明了存在主义。**

三条产品主线：

| | |
|---|---|
| 🗺️ **全城地图 + 时间轴** | 约 300 个 POI 铺在真实巴黎地图上，拖动时间轴看这座城市不同年代的文化密度 |
| 🧭 **16 条主题故事线** | 每条线有独立主题魅力，并被打上一个旅行人格标签；12 题测试帮你找到属于自己的那条 |
| 🔨 **「铭牌怎么说 vs 实际发生了什么」** | 巴黎官方铭牌自己都有错。竞品讲传说，我们讲这个传说是怎么假的 |

---

## 为什么做这个

参考境内项目 [StoryMap](https://github.com/cuizicheng1024/storymap) 的底层框架与设计思路。两点关键差异：

| | 参考项目 | 本项目 |
|---|---|---|
| 地域 | 境内 | 境外（MVP 仅巴黎） |
| 主体 | 历史人物 | **城市里的 POI** |
| 场景 | 中学教学 | 旅游 / 娱乐轻松向 |

市场侧的判断很直接：**Paris ZigZag** 是巴黎本地头部文化品牌，58 万粉丝、月访问 50 万，**却没有地图、没有 App，并且刚刚退出体验业务**。同时数据侧异常慷慨——14,760 条带片名的官方取景地、2,619 块名人铭牌、Atget/Marville 老巴黎影像全套 CC0。

## 核心设计

### 主题为主体，人格为标签

16 条故事线，每条对应一种旅行人格（4 维度 × 二分 = 16 种）。

> ⚠️ **不是「为 16 种人格各造一条线」。** 按人格造线会导致同一批 POI 换个说法讲 16 遍、内容严重同质。正确做法是**先有好主题，再判断它天然吸引哪类人**。

| # | 主题线 | 人格 |
|---|---|---|
| 1 | 一杯咖啡坐一天，顺便发明了存在主义 | 学者 NERD |
| 2 | 巴黎最有名的几块铜牌，都写错了 | 宝藏团长 CTRL |
| 3 | 《午夜巴黎》的十二点魔法 | 深藏Blue之人 BLUE |
| 4 | 海明威的穷日子 | 拾光者 MYTH |
| 5 | 蒙马特的画家们 | 干就完了 DODO |
| 6 | 拉雪兹神父公墓的名人局 | 清冷佛子 BUDD |
| 7 | 《爱在日落黄昏时》的那个下午 | 全能管家 GOAT |
| 8 | Emily in Paris 打卡路线 | 时间管理大师 TIME |
| 9 | 艾米莉的十五分钟人生 | 小蜜蜂 BEE |
| 10 | 有钱人的怪癖，后来都成了景点 | 大小姐 LORD |
| 11 | 桌上的排面：巴黎名店坐席学 | 煤老板 BOSS |
| 12 | 一个人的巴黎时刻表：从水下到屋顶 | 多比 FREE |
| 13 | 废线之上：一条被巴黎丢掉的路 | 追风筝的人 WIND |
| 14 | 一起吃、一起跳：巴黎的大桌子考古 | 慈善家 SHAN |
| 15 | 没人来赶你：巴黎的七个不走也行的地方 | 休息者 REST |
| 16 | 街头扭蛋：巴黎怪东西捡漏指南 | 史莱姆 CUTE |

核心 POI 允许大量重合——这是设计预期。同一个花神咖啡馆，在 NERD 线讲 1939 年的煤炉与存在主义谱系，在 REST 线讲「找个位子坐一下午没人赶你」。

### 内容判真法则

项目要求「交叉验证，但尽量没有人工核实素材真伪的环节」。这两件事看似矛盾，解法是把判真变成可工程化的规则：

> **能说清「为什么是这家、哪一年、什么具体细节」的掌故大概率是真的；只有一串名字的，那是菜单的一部分。**

落到字段上：每条人物-POI 关联必须填 `why_here` + `when` + `detail`，**缺一即自动降为 L4**，不进主推内容。配合 L1–L5 字段级置信度分级、独立源判定表、C1–C8 冲突规则，以及 LLM 只能读 fact sheet 的红线 + 输出后的回指校验。

这套规则在实战中立刻见效——详见下面「已经踩到的坑」。

## 已经踩到的坑

调研与语料搜集阶段的真实发现，记录在此以免重蹈：

**1. Wikidata 的人物-地点关联落不到建筑。** 实测 P19/P20/P551，绝大多数只解析到「区」级（P20 top 值是「14区 2237、16区 2163、15区 2055…」）。**「某名人住过这栋楼」不能靠 Wikidata**，必须用巴黎铭牌数据集（2,619 条）+ Open Plaques（巴黎 1,058 条）。

**2. IMDb / TMDB 都没有取景地字段，Google Places 禁止落库。** 数据源组合需要重新设计。

**3. 候选清单里有三分之一的点是死的或将死的。** 一轮核实剔除了 Chez Gégène（2024 年 12 月关门）、Les Grands Voisins（2020 年 9 月永久关闭）、La Hune（2015 年关闭，店名被买走做摄影店）、蒙帕纳斯 56 层观景台（2026 年 3 月关闭，闭园至少 4 年）、约瑟芬·贝克泳池（船体结构变形，2026 年底退役）。**不核实 `still_exists` 直接做内容，会有一批站点是空的。** 有两条线因此被迫重写主题——这反而让主题变好了。

**4. 最响亮的细节往往最不可信。** 「达利要求 Le Meurice 送一群羊到房间」被当成 `detail` 字段的标杆案例——核查发现它在 5 个以上域名可查，但**措辞逐字相同，多处明确标注转引自酒店官网**，属利益相关方单一来源。判真法则不只用来审 AI 产出，也得用来审人给的示例。

## 辟谣素材（差异化内容层）

调研副产物，也是产品最独特的一层。以下均已交叉验证：

**Le Procope「法国最老咖啡馆」整个连续性都是营销。** 1686 年那家 **1890 年就倒闭了，中间空了 67 年**，期间这地址还开过 Bouillon Chartier。1957 年才有人用同一个名字在同一堵墙里开了家新餐厅。所以店里那张「伏尔泰的大理石桌」是 1957 年以后布置进空壳里的陈设。加料：这家店现属 Groupe Bertrand——法国汉堡王的东家。

**《达芬奇密码》的「玫瑰线」是丹·布朗编的。** 巴黎人只叫它 médaillons Arago。小说还把两条不同的线混为一谈——圣叙尔比斯教堂地上那条黄铜线属于一具**日晷仪**（用来推算复活节），和阿拉戈铜牌那条**相距 115 米**。最好笑的是电影版为这条「古老神秘子午线」**付了版权费**，因为铜牌是在世艺术家 Jan Dibbets 1994 年的作品。

**钓鱼猫街不是巴黎最窄的街，而且这个谣是官方在传。** 它最窄 1.57 米；12 区的樱桃木小径最窄 **87 厘米**。维基明确指出：巴黎市政方仍把钓鱼猫街列为全市最窄，**尽管官方道路名录里记录了大量更窄的路**。

**卢米埃尔兄弟首映的地点被搞错了。** 不是和平咖啡馆（12 号），是隔壁 Grand Café 的印度沙龙（14 号，今 Scribe 酒店）。首日只卖出 33 张票。

**尼古拉·弗拉梅尔不是炼金术士。** 他是宣誓抄写员和手稿商人，1407 年盖房收容穷人，条件刻在石头上：每天早晚各祷告一次。炼金传说是死后几个世纪附会的，再由《哈利·波特》带进流行文化。

## 三条内容红线

**不能写「登上西比拉神庙」** — 肖蒙山丘那座悬崖神庙因塌方风险封闭，主体工程预计 2027 年底才开工。

**不能把巴黎大清真寺藏匿犹太儿童写成事实** — Yad Vashem 档案未结、Klarsfeld 存疑、现任院长要求谨慎。可安全讲述的替代版本：1940 年维希外交部档案怀疑该寺签发假的穆斯林归属证明，并点名了伊玛目 Abdelkader Mesli。

**小环城铁道必须逐段标注合法性** — 这条 1934 年停运的环城废线，**绝大部分路段是违法闯入而非「探险」**，只有少数改造段合法开放。不得笼统推荐。

## 技术方向

| | |
|---|---|
| 形态 | 纯静态站，桌面优先，无需登录 |
| 地图 | MapLibre GL JS + 公开 OSM 瓦片（Stamen Toner / Watercolor 等复古风底图） |
| 坐标 | 全程 WGS84（境外无需 GCJ-02 纠偏，相对参考项目是负改造量） |
| 数据流 | Markdown 语料 → parser → builder → renderer → 静态 HTML |
| 语言 | 中英双语 + 全局语言切换，法文原名在两种语言下始终显示 |

**MVP 明确不商业化**，数据源选型以「能用好用」为准，不做许可传染性隔离。

## 开发原则

1. **最小化修改** — 参考 StoryMap 代码时尽可能保持原始结构，仅在必要时做最小改动。
2. **功能降级** — 境外场景下无法实现的功能，优先降级或舍弃。
3. **确认机制** — 决定降级或舍弃前必须先沟通并获得明确确认。

一条例外：**语料库必须自建，不能偷懒。** 这是本项目的护城河。
