## 四、校验门禁实际拦住了什么

这是本轮最有价值的一件事：**判真法则从文档变成了会拦人的代码**。

`scripts/validate_corpus.py` 首次运行即抓出一条我们自己的违规：

> 夏隆讷林「在废铁轨上造林」标为 **L1**，但两个信源都是 `paris.fr`——同域名不同页不计为两个独立源，且 paris.fr 是该项目业主，属**利益相关方自述**。已按规则降为 L4 并记录 `caveat`，待第三方报道佐证后方可升级。

另外两条缺 `when` 的关联都已正确降为 L4，其中一条正是「达利的羊」教训的直接应用：

> 蓝色列车餐厅的常客名单——「香奈儿、达利、密特朗都是常客」只见于一处。**取景事实是硬的，常客名单不是。**

**门禁覆盖的规则**：三字段缺一必须降 L4 / L1-L2 需 ≥2 个独立域名 / 同域名多页折算为 1 源 / 故事线与 POI 双向引用一致 / 人格 16 种必须是 4 维二分的完整笛卡尔积 / 辟谣索引与事实源同步 / 坐标巴黎大区边界（挡经纬度写反）。

当前状态：**0 ERROR，70 WARN**（其中 55 条为坐标缺失）。

## 六、已经踩到的坑（避免重蹈）

**1. CARTO 矢量瓦片端点需要 API key，且未授权时不报错。** 它返回一张印着 `API KEY REQUIRED` 却**同时画了淡灰街道线、塞纳河形状和 `PARIS` 字样**的占位纹理，乍看很像成功加载的复古地图。识别方法：放大后看不到任何街道名（rue / boulevard / avenue）。**这个坑骗过我一次，也骗过了人眼复核。** 现已改用 OpenFreeMap（真正零 key、无配额），并把「底图无授权占位纹理」列为独立验收项。

**2. Wikidata 的人物-地点关联落不到建筑。** 实测 P19/P20/P551，绝大多数只解析到「区」级。「某名人住过这栋楼」必须用巴黎铭牌数据集（2,619 条）+ Open Plaques（巴黎 1,058 条）。

**3. IMDb / TMDB 都没有取景地字段，Google Places 禁止落库。**

**4. 候选清单里有三分之一的点是死的或将死的。** 一轮核实剔除了 Chez Gégène（2024-12 关门）、Les Grands Voisins（2020-09-30 永久关闭）、La Hune（2015 关闭，店名被买走做摄影店）、蒙帕纳斯 56 层观景台（2026-03 关闭至少 4 年）、约瑟芬·贝克泳池（船体变形，2026 年底退役）。**有两条线因此被迫重写主题——这反而让主题变好了。**

**5. 最响亮的细节往往最不可信。** 「达利要求 Le Meurice 送一群羊到房间」曾被当作 `detail` 字段的标杆案例——核查发现它在 5 个以上域名可查，但**措辞逐字相同、多处明确标注转引自酒店官网**，属利益相关方单一来源（L4）。由此定下一条产品约束：**L4 可以进内容，不能进门面；主题名只能建立在 L1–L2 素材上。**

**6. 验证环境本身会骗人。** 有一轮搜索截图里地图全白，一度以为底图又坏了。查下来是本地 Chrome 走不通容器代理（`ERR_TUNNEL_CONNECTION_FAILED`，而 curl 直连 200）。**结论：报「坏了」之前也要验证，不然会反向误报。**

## 七、三条内容红线

**不能写「登上西比拉神庙」** — 肖蒙山丘那座悬崖神庙因塌方风险封闭，主体工程预计 2027 年底才开工。

**不能把巴黎大清真寺藏匿犹太儿童写成事实** — Yad Vashem 档案未结、Klarsfeld 存疑、现任院长要求谨慎。可安全讲述的替代版本：1940 年维希外交部档案怀疑该寺签发假的穆斯林归属证明，并点名了伊玛目 Abdelkader Mesli。

**小环城铁道必须逐段标注合法性** — 这条 1934 年停运的环城废线，绝大部分路段是违法闯入而非「探险」，只有少数改造段合法开放。不得笼统推荐。
