# 结构化语料

`research/` 下的 Markdown 语料转成的结构化数据，是构建管道的输入。

**改这里的数据后必须跑校验**：

```bash
python3 scripts/validate_corpus.py
```

退出码 0 才算通过。ERROR 阻塞发布，WARN 不阻塞但会打印。

## 文件

| 文件 | 内容 | 规模 |
|---|---|---|
| `pois.json` | POI 主数据，含全部人物/作品/影视关联及其信源 | 55 个 POI，121 条关联 |
| `storylines.json` | 16 条主题线、站序、距离、语料状态 | 16 条线，57 站 |
| `personas.json` | 16 种旅行人格与四维度取值，映射到主题线 | 16 种 |
| `debunks.json` | 辟谣内容层**索引**（事实存在 pois.json，此处不重复存储） | 8 条 |

## 为什么 `debunks.json` 只是索引

辟谣素材的完整字段（`why_here` / `when` / `detail` / `sources`）存放在 `pois.json` 对应 POI 的 `associations` 中 `confidence: "L5"` 的那一项。`debunks.json` 只做索引与分类，**不重复存储事实**——两处存同一事实必然会不一致。

校验脚本会双向核对：声明 `status: "linked"` 的条目，其 `poi_id` 对应的 POI 必须真有 L5 关联；反之 POI 有 L5 素材却没被索引会报 WARN。

`status: "pending_poi"` 的 3 条（Le Procope、富兰克林制宪、伏尔泰 40 杯咖啡）属第一批 9 条线的素材，还没有 POI 记录，事实摘要暂存在 `debunks.json` 自己的字段里。

## 置信度分布

| 级别 | 含义 | 条数 |
|---|---|---|
| L1 🏛 | 有据可查 | 7 |
| L2 📎 | 大家都这么说 | 83 |
| L3 🗝 | 只有一个出处 | 11 |
| L4 ✨ | 未经证实，但很好听 | 15 |
| L5 🔍 | 著名的假故事 | 5 |

**L5 不是垃圾桶，是金矿**——竞品讲传说，本项目讲这个传说是怎么假的。

## 校验脚本实际拦住了什么

这套规则不是写在文档里好看的，它在首次运行时就抓出了真问题：

**1. 标为 L1 但两个信源同属 `paris.fr`**（夏隆讷林「在废铁轨上造林」）。同域名不同页不计为两个独立源；而且 paris.fr 是该项目业主，属利益相关方自述。已按规则降为 L4 并记录 `caveat`，待第三方报道佐证后方可升级。

**2. 三字段缺一必须降级**，脚本逐条核对。现有 2 条缺 `when` 的关联都已正确降为 L4：
- 达利的苍蝇与版画——怪癖可信度高于羊群那条，但同样缺具体年份与第三方同时代记载
- 蓝色列车餐厅的常客名单——「香奈儿、达利、密特朗都是常客」只见于一处。**取景事实是硬的，常客名单不是**

第 2 条正是「达利要了一群羊」那个教训的直接应用：最响亮的细节往往最不可信。

## 校验规则清单

**POI**：必填字段、`still_exists` 枚举、`era` ∈ 1–7、坐标格式与巴黎大区边界（挡经纬度写反）。

**关联**：`type` 枚举、`confidence` ∈ L1–L5、**三字段缺一必须已降为 L4/L5**、`sources` 非空、**L1/L2 必须 ≥2 个独立域名**、L3 有多域名时提示复核、同域名多页折算为 1 个独立源。

**故事线**：`corpus_status` ∈ complete/pending、complete 必须有站点、`order` 为从 1 开始的连续整数、站点 `poi_id` 必须存在、**与 POI 的 `storylines` 字段双向一致**。

**人格**：必须 16 种、四维度取值 ∈ high/low、**16 种必须是 4 维二分的完整笛卡尔积（不重不漏）**、一线一人格。

**辟谣**：`status` 枚举、linked 必须能在 pois.json 找到对应 L5 关联、反向检查未被索引的 L5 素材。
