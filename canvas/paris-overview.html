① 教学向模块的处置🟠 风险确认

参考项目有「人教版教材知识点」和「初高中考点」两大模块，占详情页重要版面且是语料必填章节。娱乐旅游向下不再适用。这属于功能舍弃，按你的要求需先确认。

教材知识点 / 考点模块怎么处理？
A

整体替换为「打卡提示 + 故事钩子」推荐

版面位置保留，内容换成 📸 拍什么/站哪个角度/有什么梗。改动最小且贴合旅游调性。

B

直接删除，不做替代

详情页更精简，但会空出一块版面。

C

保留，改成「冷知识 / 文化背景」

仍有知识属性但语气放松，适合想做一点科普的场景。

❓

② 主体转换后的数据模型🔵 待决策

参考项目 locations[] 是「一个人走过的多个地点」。POI 主体下有两种建模，直接决定详情页长什么样。

详情页的主角是谁？
A

双主体：POI 页 + 故事线页推荐

POI 页 = 一个地点的层层故事（谁待过/哪本书/哪部电影）；故事线页 = 一条线串起 6-8 站，直接复用参考项目的时间轴+轨迹。两者多对多。

B

只做 POI 页

更轻，但放弃了参考项目最强的「轨迹+自动播放」交互。

C

只做故事线页

和参考项目结构最像（线≈人），但 POI 无法独立被搜索到。

❓

③ 首页宏观视图的形态🔵 待决策

参考项目首页是「人类群星闪耀时」人物星图（按出生年散布）+ 中国地图分布双 Tab。POI 主体下，"星图"隐喻是否还成立？

首页第一眼看到什么？
A

巴黎地图为主 + 时间轴筛选推荐

直接进巴黎全城地图，拖时间轴看「1920s 的巴黎」逐个亮起。保留参考项目的时间轴三方联动，但砍掉星图。城市产品地图就该是第一屏。

B

双 Tab：地图 + 故事线画廊

完整对应参考项目双 Tab 结构，另一个 Tab 展示所有故事线卡片。

C

保留星图，改成「名人星图」

最接近参考项目，但和「主体是 POI」的定位有冲突。

❓

④ AI 对话能力的去留🟣 边界模糊

参考项目有人格化 AI 对话（以历史人物口吻答，可 @其他人物同框），是其亮点之一。但它依赖后端，且 POI 主体下「和谁对话」需要重新定义。

MVP 要不要做 AI 对话？
A

MVP 不做，留到 V2推荐

MVP 先把「内容 + 地图 + 故事线」做扎实。对话依赖后端服务，且纯静态站天然不支持，先降级。

B

做，角色是「巴黎本地向导」

一个统一的向导人格，基于当前 POI 的已验证事实回答，不做多角色。

C

做，和名人对话（最接近参考项目）

在海明威待过的咖啡馆和海明威聊天。有趣但内容与版权风险最高。

❓

⑤ MVP 内容规模🟡 不清楚点

调研建议 2,000 POI（100 Hero + 400 Story + 1,500 Pin）+ 12 条精品线，约 6 周。但首版可以更轻。

第一版做多大？
A

精简首发：60 POI + 8 条故事线推荐

8 条线的种子内容已经调研完成，可直接入库。先验证产品形态和内容质量，再谈规模。约 2-3 周。

B

完整方案：2,000 POI + 12 条线

覆盖全城，但需先跑通全套自动化管道，约 6 周。

C

折中：300 POI + 10 条线

覆盖核心几个街区（拉丁区/圣日耳曼/蒙马特/玛黑），约 4 周。

❓

⑥ 交付形态与语言🟡 不清楚点

参考项目是纯静态 Web 站（GitHub Pages / OpenDeploy）。我们的用户会在巴黎街头用手机看，场景不同。

做成什么形态？
A

移动优先的 Web 站，中文推荐

沿用静态站架构（最小改动），但布局以手机为第一优先 —— 用户是站在巴黎街头掏手机看。pmtiles 天然支持离线，正好解决漫游问题。

B

桌面优先（完全对齐参考项目）

改动最小，但和「行中打卡」场景不匹配。

C

移动优先 + 中英双语

可覆盖国际用户，但内容量翻倍。
